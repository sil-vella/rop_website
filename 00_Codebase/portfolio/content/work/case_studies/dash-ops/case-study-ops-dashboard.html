02 — The problem

A CLI alone is not an ops surface

Launches and builds fit a terminal menu. Drafting social posts, checking store revenue, logging expenses, and reading product docs do not — and they should not invent a second credential store in the browser.

Goal: one local window next to wfrun — same env, same runners, GUI for the rest.

03 — Ops dash

A browser twin of my automation menu

  • Scripts — grouped runners + embedded terminal; builds keep running when I change tabs
  • Task Manager — planning board embedded via same-origin proxy
  • Documentation — browse Documentation/ markdown in-app
  • Case Study — HTML narratives with Overview / Technical (this page lives there)
  • Marketing — compose, publish, platform browse, metrics
  • Revenue — estimated/settled money, downloads, expenses

04 — Revenue & downloads

Store money and installs next to ops

Revenue is not marketing. It sits under its own tab with three subtabs so money, installs, and costs stay separate — but share the same env credentials as Play / ASC / AdMob.

  • Revenue — estimated vs settled from AdMob, Play GCS sales/earnings, App Store Connect sales/finance; all-time tracked ledger + month KPIs; mixed currencies not FX-summed
  • Downloads — Play Daily User Installs (stats/installs/*_overview.csv) + ASC app download units; all-time tracked via download_entries
  • Expense — local cost log (ads, tools, hosting, …) persisted with profit = rev − exp per currency
Tracked ≠ store lifetime API. All-time grows when you widen From and Refresh — days merge into revenue_ledger.json (money and downloads kept apart).

05 — Marketing desk

Compose once, publish where I choose

Draft a post, attach media, set per-platform options, publish only to the networks I checked. Saved drafts stay local. Platform browse opens Facebook / YouTube posts with on-demand metrics. Campaign clips drip through a host cron using the same caption and token rules.

06 — Impact

What this unlocked

  • Day-to-day ops, docs, money, and social live in one local window on the same env as the CLI.
  • Manual posts and scheduled campaign drips share one contract — no per-repo drift.
  • Revenue and downloads persist locally so all-time KPIs grow with each Refresh.
  • Ported into product repos (Dutch, Arcori) without rebuilding the desk.

02 — Principles

Ops non-negotiables

  • CLI wfrun remains default; dash is opt-in.
  • Env files SSOT; never log full tokens / .p8 / SA JSON.
  • Money KPIs and download KPIs use separate ledger maps — no mixing into profit.
  • Same caption/token contract for Marketing UI and host cron.

03 — Ops dash

automation/dashboard/serve.py

  • Scripts — # dash discovery, /ws/run PTY, xterm.js; brand via REPO_BRAND
  • Task Manager — same-origin /tm/* proxy (session + CSRF)
  • Docs / Case Study — docs_discovery.py; HTML case studies only; Overview/Technical via setCaseStudyVersion
  • Marketing — routes under /api/marketing/*
  • Revenue — /api/revenue/*, /api/downloads/series, /api/expenses

04 — Revenue & downloads

Collectors + local ledger

  • AdMob — OAuth refresh + network report ESTIMATED_EARNINGS
  • Play money — GCS sales/ (estimated) · earnings/ (settled)
  • ASC money — daily salesReports · monthly financeReports
  • Play downloads — stats/installs/installs_<pkg>_YYYYMM_overview.csv (Daily User Installs; UTF-16)
  • ASC downloads — salesReports product types 1 / 1-B / F1 / 1F
  • Ledger — dashboard/data/revenue_ledger.json: entries (money, keys include app_id), download_entries (units), expenses, last_load / last_downloads_load
  • Multi-app AdMob rows must not share a day key — fixed by including app_id in persist keys

05 — Marketing desk

Compose · publish · platform browse · metrics

  • Caption: YT title+description separate; FB/TT title\\ndescription + hashtags
  • POST /api/marketing/posts multipart → only checked platforms
  • Saved JSON + media under gitignored dashboard/data/
  • Platform posts: FB / YT paged (5); TT list deferred until Production video.list
  • Metrics: FB engagement + Insights; YT videos.list?part=statistics
  • Token validate / OAuth / refresh runners; interactive env write-back

06 — Campaign queue

Slim upload; host cron; same runners

  • Upload 00renders/ + post_data.json only
  • Cron rotates products; all selected platforms must succeed before delete + log
  • Orchestrator menu-excluded; upload listed in wfrun

08 — Hard problems

What broke in the wild

  • display: grid beating HTML [hidden] on Marketing screens.
  • Task Manager CSRF fixed with same-origin /tm proxy.
  • Orphan Marketing markup outside its view panel leaked Create Post into Docs/Case Study.
  • Revenue all-time under-counted AdMob when two apps shared a day key (missing app_id).
  • Meta: User vs Page tokens; empty Insights = missing read_insights.
  • YouTube playlists needed youtube.force-ssl re-OAuth.
